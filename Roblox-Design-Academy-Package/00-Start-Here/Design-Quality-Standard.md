# Design Quality Standard

A feature is **done** only when:
1. **It works** (functional).
2. **It is clear** — passes squint, greyscale and stranger tests (UI-001, THUMB-002).
3. **It responds** within 0.1 s to input (FEEL-007).
4. **It fits the identity statement** (ID-001) and uses shared components/tokens (UI-005).
5. **It is readable on a phone** with accessibility settings at their extremes (TECH-003).
6. **It is honest** — marketing matches the game, odds are disclosed (THUMB-010, PROG-005).
7. **It performs** on the baseline device (TECH-006).
8. **It survived critique** — design critique checklist with weaknesses written first.

Priority order when trading off (default, not law): core-loop clarity → moment-to-moment satisfaction → readability/responsiveness → meaningful progression → reward feedback → visual identity → UI polish → long-term replayability. Exceptions: in roleplay/social sandboxes, expression tools and identity may outrank progression; in horror, atmosphere may outrank UI polish.
