# Design Critique Checklist (run before calling anything finished)

Run for each UI screen, thumbnail, icon, animation and VFX. **Write a concrete observation for every row** — "looks good" is not an answer. Score 0–2 per criterion (0 = fails, 1 = partly, 2 = clearly meets) **with the evidence sentence**; any 0 blocks completion.

| Criterion | Question to answer in writing | Evidence required |
|---|---|---|
| Identity fit | Which identity-statement decision does this express? | Name the motif/palette/type used |
| Clarity | What is the one thing a player understands in 1 s? | Stranger test or squint test result |
| Composition | Where does the eye go first, second, third? | Blur screenshot |
| Hierarchy | What is primary, secondary, tertiary? | List them |
| Readability | Smallest text size on phone? Contrast? | Device screenshot |
| Responsiveness | What happens within 0.1 s of input? | Recording timestamp |
| Emotional impact | Which emotion (from the statement) and how? | One sentence |
| Distinctiveness | Placed beside 3 competitors, what makes it ours? | Side-by-side image |
| Consistency | Which shared components/tokens does it use? | Component names |
| Functional usefulness | Which player decision/question does each element serve? | Element → purpose list |
| Honesty | Does it represent the real game/odds? | Capture source / odds table |
| Performance | Cost on baseline device? | FPS/memory note |

## Anti-approval rules
1. List at least **three weaknesses** before listing strengths.
2. Compare against two academy references of the same type ([Master Index](../00-Start-Here/Master-Index.md)).
3. If a criterion was not checked, mark ⬜ — never assume.
4. Record lessons in the vault.
