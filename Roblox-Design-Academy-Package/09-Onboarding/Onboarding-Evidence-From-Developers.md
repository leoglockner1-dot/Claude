# Onboarding Evidence from Developers (DevForum, 2026)

Developer-posted numbers; not independently verified.
| Case | Reported data | Diagnosis (community / developer) | Source |
|---|---|---|---|
| Troll tower obby | Onboarding completion 30.03 %; 48 % churn at "Shop Opened"; 3.13 % reach floor 2 | Forced blurred tutorial teaching the shop; arrows unexplained | [ONB-06](Analyses/ONB-06-DevForum-Forced-Blur-Tutorial-Funnel.md) |
| TURBOSTORM racing | ~10 min average session from ads; zero organic traffic | Name discoverability, first 5 s of video, low-graphics world | [CS-15](../15-Game-Case-Studies/CS-15-TURBOSTORM-Racing.md) |

| Low avg playtime game | ~5 min vs 13–30 min genre peers | Reviewer: FTUE is the main reason; dev changed to start with selling + camera transition | <https://devforum.roblox.com/t/low-average-play-time/4825594> |
| Roll a Cupcake | Players "walk around aimlessly and leave despite the tutorial" | Small arrows, AI-looking UI | [UI-25](../01-UI-UX/Analyses/UI-25-DevForum-Roll-a-Cupcake-AI-Look.md) |
| 8 Ball Duels | 50–60 % approval vs ~75 % competitors | First-shot control unclear → "game seemed broken"; ad traffic lowers ratings (another dev: 76 %→60 %) | <https://devforum.roblox.com/t/game-has-terrible-ratings/4867245> |
| Outbreak Mayhem | 64 % likes | Point of the game unclear; later "sightreadable" objectives | [CS-17](../15-Game-Case-Studies/CS-17-Outbreak-Mayhem.md) |

## Patterns (Medium confidence)
1. The first control interaction must work obviously (8 Ball).
2. Teach the core verb, not the shop (troll tower).
3. Arrows must be big and explained (cupcake, troll tower).
4. Ad traffic is less targeted — expect lower ratings and shorter sessions; judge changes with Experiments, not raw daily numbers.
