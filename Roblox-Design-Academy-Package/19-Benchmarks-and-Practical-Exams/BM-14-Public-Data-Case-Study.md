# BM-14 — Case study from public data only

| Field | Value |
|---|---|
| Area | Research |
| Level | Beginner |
| Time box | 60 min |
| Status | ✅ Executed by the academy |

## Task
Write a case study of a live Roblox game using only public data (description, votes, passes, thumbnails), labelling every inference and stating that gameplay was not observed.

## Inputs
- Roblox public APIs (games, votes, game passes).

## Deliverables
- A note in the case-study template with data date and sources.

## Acceptance criteria (pass/fail)
- [ ] Every number has a source and date.
- [ ] The core loop is labelled as inferred.
- [ ] One original application that does not copy the game's identity.

## Scoring rubric (0 / 1–2 / 3)
| Dimension | 0 | 1–2 | 3 |
|---|---|---|---|
| Sourcing | Unsourced | Partly | All sourced and dated |
| Labelling | Inference as fact | Some labels | All labelled |
| Originality | Copies | Generic | Specific, original |

## Common failure modes
- Describing gameplay never seen.
- Claiming causation from like ratios.

## Self-critique before submitting
Run the [Self-Critique Loop](../18-Skill-Training/Self-Critique-Loop.md): state the criteria **before** looking at the result, inspect the output (not your intention), and log every failed version.
