# GM-16 — Discovery (learning hidden rules and content)

| Aspect | Notes |
|---|---|
| **What the player does** | Uncovers how things work or what exists: recipes, secret levels, enemy weaknesses, lore. |
| **Skill or decision involved** | Experimentation, deduction, memory. |
| **Feedback needed** | "Aha" confirmation (journal entry, unlock fanfare), hints that point without telling. |
| **Why it can be satisfying** | Knowledge is progression that cannot be bought; communities form around shared secrets. |
| **Design conditions under which it works** | Hints must exist for players who get stuck (timed hints, [ONB-05](../13-Onboarding-and-Multiplayer/Onboarding/Analyses/ONB-05-Plant-Timed-Hints.md)); discoveries must matter in play. |
| **How difficulty can scale** | More obscure combinations; multi-step secrets. |
| **How progression can change it** | Journals/indexes that fill; secret areas (Speed Run 4 forbidden levels [DEV]). |
| **What causes repetition fatigue** | Secrets that are pure busywork; information only available on wikis. |
| **Exploits and edge cases (Roblox-specific where relevant)** | Datamining reveals secrets (expect it; design for discovery, not secrecy). |
| **Genres it fits** | Horror (DOORS "use each death as a lesson" [DEV]), puzzle, crafting, RPG. |
| **Genres it does not fit (or fits badly)** | Pure skill competition. |
| **Original variations** | Each failed attempt reveals one new clue (death as information). |
| **Prototype and testing guidance** | 3 hidden interactions and a journal; measure discovery rate with and without hints. |
