# GM-07 — Building

| Aspect | Notes |
|---|---|
| **What the player does** | Places pieces to create structures, bases, vehicles, rooms. |
| **Skill or decision involved** | Spatial planning, creativity, engineering trade-offs (cost, strength, layout efficiency). |
| **Feedback needed** | Placement preview (ghost), snap feedback, validity colour (green/red), the built thing being *used* (guests, voyages, defense). |
| **Why it can be satisfying** | Ownership and self-expression; seeing your design work. |
| **Design conditions under which it works** | Grid/snap support (the environmental-art curriculum uses 5-stud snapping), undo, templates to beat blank-canvas paralysis (Restaurant Tycoon 3 added starter templates [DEV]), mobile-friendly controls. A *test* of the build makes it a game, not just a tool. |
| **How difficulty can scale** | Budget limits, structural physics, hostile attacks, space limits. |
| **How progression can change it** | New pieces, larger plots (often monetized: Theme Park Tycoon 2, Bloxburg passes [DATA]), advanced placement tools. |
| **What causes repetition fatigue** | Building with no purpose or audience; tedious placement UI. |
| **Exploits and edge cases (Roblox-specific where relevant)** | Overlapping parts to break physics; lag machines (part count limits); offensive builds (moderation). |
| **Genres it fits** | Tycoons, sandboxes, survival bases, life sims. |
| **Genres it does not fit (or fits badly)** | Fast round-based action (unless quick build like BedWars bridges). |
| **Original variations** | Build under a timer then defend; build cooperatively where each player only has one piece type. |
| **Prototype and testing guidance** | 5 pieces, snap grid, a purpose test (wave of balls hitting the wall); test whether players iterate designs. |
