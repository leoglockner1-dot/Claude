# GM-12 — Escaping

| Aspect | Notes |
|---|---|
| **What the player does** | Leaves a dangerous place by solving, finding or outrunning. |
| **Skill or decision involved** | Navigation, puzzle-solving, evasion. |
| **Feedback needed** | Progress toward exit (keys found, doors unlocked), pursuer proximity cues (sound + visual), a release moment on escape. |
| **Why it can be satisfying** | Clear goal + threat = tension; escape is a natural climax. |
| **Design conditions under which it works** | The exit and the steps toward it must be legible; pursuers need fair counter-play; audio cues need visual equivalents. |
| **How difficulty can scale** | Faster/smarter pursuers, randomized item locations, fewer hiding spots. |
| **How progression can change it** | New maps/chapters, tools that change routes. |
| **What causes repetition fatigue** | Fixed solutions memorized; unfair instant deaths. |
| **Exploits and edge cases (Roblox-specific where relevant)** | Clipping through walls, exploiting pursuer pathfinding. |
| **Genres it fits** | Horror, escape rooms, obby finales, asymmetric 1vN. |
| **Genres it does not fit (or fits badly)** | Sandboxes with no goal. |
| **Original variations** | Escape where the world collapses behind you; escape that requires carrying a teammate. |
| **Prototype and testing guidance** | One map, 3 keys, one pursuer bot; measure escape rate and session-to-session improvement. |
