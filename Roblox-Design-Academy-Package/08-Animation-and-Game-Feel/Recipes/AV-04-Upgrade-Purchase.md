# AV-04 — Upgrade purchase

| Step | Specification |
|---|---|
| **Trigger** | Press on Buy (instant local feedback) → server confirmation (result feedback). |
| **Timing** | Press: AV-01. Confirm: two-note rise 0.3–0.6 s (preview 0.47 s); stat change visible within 0.3 s of confirmation. |
| **Anticipation** | Button shows "pending" (spinner or dim) if confirmation takes >150 ms. |
| **Main action** | Cost flies from the wallet to the item; the upgraded object visibly changes (size/colour/new part). |
| **Impact** | The upgraded object pops (Back Out) + the confirm sound. |
| **Follow-through** | The new stat line highlights for ~1 s; the next upgrade cost shows. |
| **Sound** | Bright two-note rise + shimmer **on server confirm**, not on press. |
| **Visual hierarchy** | Show what changed, not just the number. |
| **Performance considerations** | Single tween set; no particles needed for common upgrades. |
| **When restraint is preferable** | Bulk buys (x10, max): one combined celebration, not ten. |
| **Roblox implementation** | RemoteFunction result → play the confirm; on failure play AV-05 with the reason ([LU-07](../../07-Roblox-Studio-and-Luau/LU-07-Currency-and-Shop.md)). |
| **Evidence and previews** | Sound ([wav](../../Assets/Original/AV/AV-04_purchase_confirm.wav), [waveform](../../Assets/Original/AV/AV-04_purchase_confirm-waveform.jpg)); official upgrade-button baseline [V12](../../21-Video-Analyses/V12-Upgrade-Button-Baseline.md); [R04](../../18-Skill-Training/Design-Recipes/R04-Upgrade-Purchase-Interaction.md). |

**Test:** play it 20 times in a row. Is it still pleasant? Does it still read at phone size? Is the meaning clear with the sound off and with the visuals ignored (sound only)?
