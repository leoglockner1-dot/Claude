# AV-02 — Menu and panel transitions

| Step | Specification |
|---|---|
| **Trigger** | Open/close a panel (shop, inventory, settings). |
| **Timing** | Open 0.18–0.25 s (Quad/Cubic Out); close 0.12–0.18 s (faster than open). Roblox's accessibility doc sample uses 0.75 s Cubic Out for a settings menu, which is slower than this house guidance for frequent panels. |
| **Anticipation** | None (instant response matters more); optionally the background dims first by 0.05 s. |
| **Main action** | Slide 20–40 px + fade in, or scale 0.95→1. |
| **Impact** | Panel content readable by ~70% of the tween. |
| **Follow-through** | Contents stagger in at 20–30 ms per row (max 5 rows staggered). |
| **Sound** | Soft whoosh/tick ≤150 ms; none for tiny popovers. |
| **Visual hierarchy** | The panel title and primary action appear first; decorative elements last. |
| **Performance considerations** | Animate a `CanvasGroup` for group fades; avoid animating many layout children. |
| **When restraint is preferable** | Panels opened dozens of times per session (inventory): reduce to a 0.12 s fade. Respect any reduced-motion setting you offer. |
| **Roblox implementation** | CanvasGroup.GroupTransparency + UIScale tweens; disable the gameplay input context while open ([LU-15](../../07-Roblox-Studio-and-Luau/LU-15-Input-Handling.md)). |
| **Evidence and previews** | [Timing Reference](../Timing-Reference.md); reward-pop preview ([AV-02_reward_pop.gif](../../Assets/Original/AV/AV-02_reward_pop.gif)); [R01](../../18-Skill-Training/Design-Recipes/R01-Polished-Main-Menu.md). |

**Test:** play it 20 times in a row. Is it still pleasant? Does it still read at phone size? Is the meaning clear with the sound off and with the visuals ignored (sound only)?
