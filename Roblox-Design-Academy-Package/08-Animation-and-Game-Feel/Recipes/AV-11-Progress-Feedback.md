# AV-11 — Progress feedback (bars, counters)

| Step | Specification |
|---|---|
| **Trigger** | A tracked value changes. |
| **Timing** | Bar change visible within ≈0.25 s (an official HUD meter used an Exponential Out 0.5 s tween with most change in ≈0.25 s); counters count up over 0.3–0.6 s. |
| **Anticipation** | "Ghost" bar shows the target instantly; the main bar catches up. |
| **Main action** | Bar slides; counter rolls. |
| **Impact** | Pulse on completion (Back Out). |
| **Follow-through** | Next goal label updates. |
| **Sound** | Optional soft ticks during count-up (cap rate); a completion chime. |
| **Visual hierarchy** | Show "x / y" or the time remaining near bars ([First-Session Design](../../13-Onboarding-and-Multiplayer/Onboarding/First-Session-Design.md)). |
| **Performance considerations** | Springs/tweens on one value; no per-frame string formatting unless the value changed. |
| **When restraint is preferable** | Constantly changing values (idle income): update the text 4–10×/s, not every frame. |
| **Roblox implementation** | `Feel.springStep` for chasing bars, `Feel.abbreviate` for text ([LU-16](../../07-Roblox-Studio-and-Luau/LU-16-Tweens-and-Springs.md), [LU-27](../../07-Roblox-Studio-and-Luau/LU-27-HUD-Number-Formatting.md)). |
| **Evidence and previews** | [V06/V07 health bar strips](../../21-Video-Analyses/V06-V07-HUD-Meter-Tween-and-Damage-Flash.md); [easing curves](../../Assets/Original/AV/easing-curves.png). |

**Test:** play it 20 times in a row. Is it still pleasant? Does it still read at phone size? Is the meaning clear with the sound off and with the visuals ignored (sound only)?
